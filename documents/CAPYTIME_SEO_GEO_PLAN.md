# План SEO и GEO для capytime.ru

**Продукт:** CapyTime — бесплатный сервис онлайн-записи клиентов к специалистам.
**Дата:** 2026-05-30. **Аудитория плана:** владелец продукта / маркетинг / фронтенд-команда.

GEO здесь — **Generative Engine Optimization** (оптимизация под ответы ChatGPT,
Perplexity, Claude, Алисы/Поиска Яндекс с YandexGPT, GigaChat). SEO — классический
органический трафик из поиска Яндекса/Google.


## 1. Текущее состояние (по аудиту главной)

| Сигнал | Состояние | Комментарий |
|---|---|---|
| Тип сайта | SPA (Vite-бандл) | На главной отдаётся ~1.5KB HTML; контент рендерится в браузере. Краулеры видят **только title + description + favicon**. |
| `<title>` | «CapyTime — бесплатная и простая запись клиентов» | Корректный, но слишком общий, без ниши/ключевиков/конкурентов. |
| `meta description` | Есть, ~140 симв. | Без CTA, без ниши, без географии. |
| Open Graph / Twitter | Базовые поля есть | Нет `og:image`, `twitter:image` — превью в соцсетях/мессенджерах пустое. |
| H1/H2/H3 | В исходном HTML отсутствуют | Все заголовки рендерятся JS — не индексируются без SSR/prerender. |
| Внутренние ссылки в исходнике | Нет (только CSS + JS) | Нет графа страниц для краулеров. |
| `robots.txt` | OK, всё разрешено для Googlebot/Bingbot/Twitterbot/Facebook | |
| `sitemap.xml` | **Отсутствует** (URL возвращает fallback-HTML главной) | Критично. |
| Маршруты SPA | `/booking`, `/onboarding`, `/schedule`, `/privacy-policy`, `/terms-of-service`, `/personal-data-processing` | Публичные `/booking` и `/onboarding` потенциально SEO-ценные. |
| `google-site-verification` | Подключен | Search Console уже настроена. |
| Yandex Webmaster | Не виден метатег в исходнике | Скорее всего НЕ подключен. |
| Структурированные данные (JSON-LD) | Нет | Нет Organization, SoftwareApplication, FAQPage, BreadcrumbList. |
| Региональные/нишевые посадочные | Нет | Главное упущение для трафика этого класса продуктов. |
| Блог / контент-хаб | Нет | Нет источника длинных хвостов и GEO-цитирования. |

**Главный диагноз:** для поисковых систем сайт сейчас — это одна страница в полтора
килобайта. Любая SEO-работа поверх этой архитектуры даст 5–10% от потенциала, пока
не решена проблема рендеринга и нет структурированного контента.

## 3. SEO — техническое

### 3.1 Решить рендеринг (критично, без этого остальное не работает)

Три варианта в порядке предпочтения:

1. **Prerender при сборке (наиболее реалистично для Vite-SPA)** — vite-plugin-prerender
   или Prerender.io: ключевые публичные маршруты (`/`, `/booking`, `/onboarding`,
   страницы ниш и регионов, блог) собираются в HTML на этапе деплоя. Минимум
   изменений архитектуры.
2. **Переезд на SSR** — Next.js / Nuxt / SvelteKit, если планируется большой блог
   и динамические посадочные. Стратегически правильнее, но требует переписи
   фронтенда.
3. **Dynamic rendering** — отдавать ботам предрендеренные snapshot'ы через
   Prerender.io как промежуточный шаг. Быстро, но Google это не любит как
   постоянное решение.

Рекомендация: **вариант 1 на ближайший квартал**, переход на 2 — когда вырастет блог.

### 3.2 Sitemap и каноникал
- Сгенерировать `sitemap.xml` со всеми публичными маршрутами + посадочными +
  статьями блога, обновлять при деплое.
- Добавить `sitemap.xml` в `robots.txt` (`Sitemap: https://capytime.ru/sitemap.xml`).
- На каждой странице — `<link rel="canonical">`.
- Загрузить sitemap в **Google Search Console** и **Яндекс.Вебмастер**.

### 3.3 Подключить Яндекс.Вебмастер
- Добавить метатег `yandex-verification`.
- Прописать регион в Вебмастере, привязать к Яндекс.Бизнесу (карточке).
- Подключить мониторинг ИКС, переобход страниц.

### 3.4 Микроразметка JSON-LD
На главной и на каждом типе страницы:
- `Organization` (логотип, контакты, sameAs со всеми соцсетями).
- `SoftwareApplication` / `WebApplication` для самого продукта (priceRange = «0»,
  applicationCategory = «BusinessApplication», aggregateRating с реальными отзывами).
- `FAQPage` на главной и нишевых страницах (см. блок GEO).
- `BreadcrumbList` на внутренних.
- `Article` в блоге.
- `LocalBusiness` для региональных посадочных (если будут локальные офисы/представители).

### 3.5 Core Web Vitals
- Кодсплиттинг тяжёлого бандла (239KB JS) — динамический импорт для `/schedule`
  и подобных тяжёлых приватных страниц.
- `<link rel="preconnect">` к API-домену.
- WebP/AVIF для изображений, `loading="lazy"`.
- Цель: LCP < 2.5s, INP < 200ms, CLS < 0.1 на мобайле.

### 3.6 Безопасность и доверие
- HTTPS уже есть.
- Добавить `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`.
- На страницах с формами — явная ссылка на политику конфиденциальности (уже есть `/privacy-policy`).

### 3.7 Аналитика
- GA4 + Яндекс.Метрика (если ещё нет), цели на регистрацию/первое бронирование,
  carouselWebvitals, scroll-глубина, исходящие клики.
- UTM-разметка из всех каналов.

### 4.7 Шаблон страницы (минимум для каждой посадочной)
- H1 с целевым ключом
- Подзаголовок-обещание + CTA на регистрацию (≤1 экрана)
- Скриншот/демо
- 3–5 проблема→решение блоков (с H2)
- Сравнительная таблица «без CapyTime / с CapyTime» или с конкурентом
- Соцпруф (отзывы, логотипы, числа)
- FAQ (6–10 Q&A, в JSON-LD)
- Финальный CTA + footer

## 5. SEO — ядро ключевых слов (стартовый каркас)

Разбить на кластеры. Собрать в Wordstat / Keys.so / Topvisor, заложить
по 30–80 запросов в каждый кластер.

**Кластер «продукт» (high-intent, мало частотности, высокая конверсия):**
бесплатная онлайн запись клиентов, сервис записи клиентов бесплатно,
программа для записи клиентов бесплатно, бесплатный crm для записи,
бесплатный аналог yclients.

**Кластер «ниша» (high-intent, средняя частотность):**
онлайн запись для парикмахера/мастера маникюра/массажиста/психолога…,
программа для барбершопа, расписание для репетитора онлайн,
crm для коуча бесплатно, запись клиентов мастер на дому.

**Кластер «функциональный» (средняя intent):**
напоминания клиентам онлайн, отправка sms клиентам напоминание о записи,
телеграм бот для записи клиентов, виджет онлайн записи бесплатно,
гугл календарь синхронизация записи клиентов.

**Кластер «гео+ниша» (long-tail):**
{город} + {ниша} + «онлайн запись».

**Кластер «информационный» (для блога и GEO):**
как принимать предоплату, как не забывать о записях,
шаблон сообщения клиенту, как настроить онлайн запись,
crm для самозанятых для записи.

**Кластер «конкуренты»:**
yclients альтернатива бесплатная, что лучше altegio или…, отзывы yclients,
аналог gbooking.

## 8. GEO (Generative Engine Optimization)

Цель — попасть в ответы ChatGPT/Perplexity/YandexGPT/GigaChat/Claude на запросы:
- «Бесплатный сервис для онлайн-записи клиентов»
- «Альтернатива YClients/Altegio бесплатная»
- «Как организовать запись клиентов мастеру маникюра/парикмахеру/психологу»
- «Куда переехать с YClients, чтобы было бесплатно»

### 8.1 Что любят LLM (общий принцип)
- **Прямые ответы в первом абзаце** на конкретный вопрос (формат «Что такое X — Y.»).
- **FAQ-блоки** в JSON-LD: подгружаются в индекс и в SGE-сниппеты.
- **Сравнительные таблицы** с прямыми названиями конкурентов — цитируются дословно.
- **Списки с критериями выбора** («7 признаков хорошего сервиса записи»).
- **Свежие даты** (обновлено YYYY-MM) — LLM учитывают актуальность.
- **Внешние авторитетные упоминания** — основной сигнал для языковых моделей,
  они учились на текстах vc.ru, Habr, Wikipedia, отзывных площадок.

### 8.2 Что сделать на сайте
1. На главной — секция «Что такое CapyTime» c прямым однопредложным ответом
   («CapyTime — это бесплатный сервис онлайн-записи клиентов для специалистов,
   работающих с клиентами по записи: парикмахеров, мастеров маникюра, психологов,
   коучей, репетиторов»). Это и есть «answer chunk» для GEO.
2. На каждой посадочной — FAQ из 6–10 вопросов с прямыми краткими ответами.
   В разметку — `FAQPage` JSON-LD.
3. Сравнительные страницы (см. 4.3) — таблицы с YClients, Altegio, GBooking,
   честные плюсы и минусы, цены, ограничения.
4. «Глоссарий» отрасли — `/glossariy`: онлайн-запись, no-show, предоплата,
   виджет, депозит и т.п. По 200–400 знаков на термин. LLM любят такие словари.
5. Страница «О сервисе / About» с структурой:
   - дата основания, команда, контакты, юр. лицо;
   - чек-лист функций;
   - принципы работы с данными;
   - sameAs ссылки в JSON-LD.
6. `llms.txt` (новый формирующийся стандарт, обсуждается в OpenAI/Anthropic
   сообществе) — отдать в корне краткое описание + ссылки на ключевые
   страницы для удобства парсинга моделями. Низкий риск, потенциальная выгода.

### 8.3 Что сделать ВНЕ сайта (важнее, чем on-page для GEO!)
1. **Wikipedia / Wikidata** — добавить сущность «CapyTime» в Wikidata (это легче,
   чем статью в Wikipedia, и идёт в обучающие данные).
2. **Статьи на vc.ru / Habr / Tinkoff Journal** — обучающие материалы со
   ссылкой на сайт. LLM сильно опираются на vc.ru и Habr по русскому корпусу.
3. **Обзоры на агрегаторах:** Startpack, Soware, Otzyvmarketing, Spark — каждое
   упоминание даёт сигнал и LLM, и поиску.
4. **Сравнения от блогеров** в YouTube/Telegram — расшифровки выдачи прорастают
   в обучающие корпуса.
5. **Подкасты** для бьюти/коуч-индустрии — гости с упоминанием продукта.
6. **Отзывы клиентов** на otzovik.com, irecommend.ru, Yandex Бизнес — реальные,
   развёрнутые.
7. **Quora-аналоги (Ответы Mail.ru)** — длинные ответы экспертов на «какой
   сервис записи выбрать».

### 8.4 Мониторинг GEO
Раз в неделю задавать 30–40 канонических запросов в ChatGPT, Claude, Perplexity,
Алисе/Поиску Я с YandexGPT, GigaChat, фиксировать:
- упомянут ли CapyTime;
- в каком контексте (рекомендация / упоминание / нет);
- какие источники LLM цитирует.

Сводить в таблицу, обновлять то, что не попадает, дополнять контент под пробелы.

- Дозаполнить ядро: ещё 10–15 ниш и 10 городов.
- Поднять рейтинг карточек на агрегаторах.
- Партнёрские интеграции (Тинькофф для самозанятых и т.п.) — лендинги под них.
- Кварт. PR-волна для бэклинков из СМИ.
- Анализ позиций, расширение того, что растёт.

## 10. Quick wins (что даст эффект в первый месяц при минимуме усилий)

1. **Sitemap + Я.Вебмастер** — открывает индексацию вообще.
2. **Prerender главной + 5 ключевых страниц** — переводит сайт из «невидимого»
   в «видимый» для краулеров. Самый большой рычаг.
3. **`og:image` + `twitter:image`** — мгновенный рост CTR при шеринге.
4. **JSON-LD Organization + FAQPage на главной** — даёт rich-snippets и попадание в GEO.
5. **Я.Бизнес карточка** — локальные показы в Картах по всей РФ.
6. **5 первых нишевых посадочных** с FAQ — мгновенный длинный хвост.
7. **Один обзорный пост на vc.ru** — мощный одноразовый сигнал и для SEO, и для GEO.
8. **«Бесплатная альтернатива YClients» лендинг** — самый high-intent трафик из
   уходящих от платных конкурентов.

## 12. Риски и ограничения

- Без решения проблемы рендеринга остальная работа даст 5–10% возможного. Это
  пункт №1 в roadmap, всё остальное — следствие.
- Конкуренты (YClients, Altegio) — старые сильные домены с большим бэклинк-профилем.
  Победа по brand-запросам конкурентов — реалистично только через «альтернатива»-лендинги
  + сильные обзоры на vc.ru/Habr.
- В РФ Яндекс важнее Google (≥60% доли). Все техрешения и контент тестировать в
  первую очередь под Яндекс (региональность, ИКС, поведенческие).
- GEO — относительно новая область с быстро меняющимися правилами. Раз в месяц
  пересматривать стратегию по результатам мониторинга.
